# 프로젝트 멘토링 질문

1. Redis에서 재고 차감에는 성공했지만 Kafka 메시지 발행에 실패한 경우, 실무에서는 재시도·재고 보상·Outbox Pattern 중 어떤 방식으로 처리하는 것이 적절한가요?

2. Redis 단독 방식은 DB 저장 완료 후 응답하고 Redis+Kafka 방식은 요청 접수 후 `WAITING`으로 응답합니다. 처리 범위가 다른 두 방식을 어떤 기준으로 측정해야 공정하게 비교할 수 있나요?

3. DB 직접 처리, 비관적 락, 낙관적 락, 조건부 UPDATE, Redis를 비교할 때 반드시 동일하게 통제해야 할 조건은 무엇이며, TPS·p95·p99·성공률·정합성 외에 어떤 지표를 확인해야 하나요?

4. 현재 Redis만으로 재고 동시성은 제어할 수 있습니다. 이 프로젝트에서 Kafka까지 도입하는 것이 적절한지, Kafka 도입 여부를 판단할 때 어떤 지표와 요구사항을 기준으로 삼아야 하나요?

5. Redis에서 재고를 먼저 확보하고 Kafka는 DB 저장만 담당하는 구조와, 요청 자체를 Kafka에 넣고 Consumer가 재고를 확보하는 구조 중 선착순 쿠폰 시스템에는 어떤 방식이 더 적절한가요?

6. 최종 프로젝트에서 모든 장애 상황을 구현하기 어렵다면 멱등성, Kafka 재시도, Redis 재고 보상, 정합성 검증·복구, 모니터링 중 어떤 항목을 우선 구현해야 하나요?

7. 현재 단계별 테스트 후 최대 재고 10,000개·요청 20,000건을 계획하고 있습니다. 트래픽 예측 자료가 없을 때 테스트 규모와 반복 횟수가 충분한지를 어떤 기준으로 판단하나요?

8. 실제 클릭 시점과 서버 도착 시점에 차이가 있는데, 대규모 선착순 시스템에서는 일반적으로 어느 시점을 선착순 기준으로 정하나요? Redis `INCR`로 생성한 순번을 기준으로 사용하는 것이 적절한가요?
